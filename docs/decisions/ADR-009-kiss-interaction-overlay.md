# ADR-009: 采用全局覆盖层实现特殊互动（Kiss）

## Status
Accepted

## Date
2026-04-30

## Updates
- 2026-06-30: 覆盖层方案已经从最初的 `kiss` 专用表现扩展为通用的双人特殊互动表现层，当前还覆盖 `hug`、`cultivate`、`shareFood` 和 `throwup` 等组合图资源。后续维护时应把本 ADR 理解为“单张双人组合图使用全局 overlay 展示”的通用决策，而不是只适用于亲吻动画。

## Context
目前应用中的宠物动画主要是基于 Emoji 的简单字符替换（或者单张静态图片）。当两只宠物靠近并触发互动（如 `kiss`）时，原有的方式只是在宠物头顶产生特效 Emoji（如 ✨），并且改变宠物身体的 Emoji。

但随着图片美术资产的引入（我们有了单独的 `kiss.png` 表现两只宠物亲吻的场景，而不是各自独立的动作帧），我们需要一种机制来展示这种“双人组合图”。因为这是一张单图，所以无法简单地把它赋给单独某一个宠物。

## Decision
我们决定在 `kiss` 等特殊的双人互动发生时，引入 **Overlay（覆盖层）模式**：

1. 当互动触发时（由 `InteractionSystem` 派发），`app.js` 通知 `PetRenderer` 开启 `kissOverlayActive` 状态。
2. `PetRenderer.showKissOverlay()` 会被调用：
   - 将两只宠物原本的 DOM 节点内的 `.pet-body` 设置为 `visibility: hidden`（保留占位但不显示各自的图片）。
   - 在两只宠物位置的中心点，生成一张绝对定位的 `<img id="kiss-overlay">`（展示 `kiss.png`）。
3. 互动结束时，`app.js` 通知隐藏 overlay，并恢复原有的 `.pet-body` 的显示。

## Alternatives Considered
*   **拆分图片为独立帧**：让画师或者通过工具将 `kiss.png` 从中间裁开，分发给 `yueqi` 和 `shenjiu` 各自显示半边。
    *   *缺点*：需要额外处理图片。而且如果后续互动有交叠（比如拥抱），很难完美裁切成完全不重叠的两半，且在屏幕上拼合可能出现 1px 的裂缝或者错位问题。
*   **把其中一个宠物隐藏，让另一个显示合体图**：
    *   *缺点*：逻辑不对等，且坐标计算需要以一方为基准偏移，不够直观。

## Consequences
*   **优点**：
    *   实现简单，美术提供单张双人互动图即可，降低美术和动画处理成本。
    *   画面不会出现拼合裂缝，确保完美展现。
    *   DOM 结构的隐藏/显示处理起来开销极小。
*   **缺点**：
    *   如果宠物原本位置差距较大或发生了移动碰撞错误，在突然变成固定距离的组合图时视觉上会有瞬移感。（但在目前的机制下，触发互动时两人已经处于较近的特定距离内，所以视觉突兀感不强）。
