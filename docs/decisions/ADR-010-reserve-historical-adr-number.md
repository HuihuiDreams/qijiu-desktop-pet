# ADR-010: 保留历史 ADR 编号空缺

## Status
Accepted

## Date
2026-06-01

## Context
`docs/decisions/` 中已经存在 `ADR-001` 到 `ADR-030` 的决策记录，但历史上跳过了 `ADR-010`，后续文档、变更记录和代码注释已经引用了 `ADR-011` 及之后的编号。

ADR 编号应尽量连续，方便检索和引用；但已经被引用的 ADR 编号也是公共文档接口，不能为了补齐序号而随意重排。

## Decision
保留 `ADR-010` 作为历史编号空缺记录，不重命名 `ADR-011` 及之后的现有 ADR。

未来新增 ADR 从当前最大编号继续递增，不复用已发布或已保留的编号。

## Alternatives Considered
### 重命名 `ADR-011` 到 `ADR-030`
- 优点：编号能恢复完全连续。
- 缺点：会破坏已有链接、变更记录和历史讨论中的引用。
- 结论：拒绝。ADR 编号一旦被引用，就应视为稳定标识。

### 将下一条真实决策写入 `ADR-010`
- 优点：可以填补空号。
- 缺点：时间顺序会倒置，后续读者可能误以为该决策早于 `ADR-011` 到 `ADR-030`。
- 结论：拒绝。编号补洞不应制造新的时间线混乱。

## Consequences
- ADR 文件序列中不再缺少 `ADR-010`。
- 现有 `ADR-011` 及之后的链接保持稳定。
- 后续新增 ADR 需要继续使用下一个递增编号，而不是复用历史空号。
