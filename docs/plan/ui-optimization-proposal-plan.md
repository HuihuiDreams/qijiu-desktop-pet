# 桌宠 UI 优化提案

> 状态：提议中  
> 范围：只记录建议，不修改程序代码  
> 最后更新：2026-06-22  
> 相关 ADR：[ADR-033](../decisions/ADR-033-frontend-ui-engineering-and-color-swap.md)、[ADR-034](../decisions/ADR-034-ui-performance-and-visual-upgrades.md)、[ADR-039](../decisions/ADR-039-city-setting-ui-window.md)

## 1. 这份提案想解决什么

当前 UI 已经有一个明确方向：仙侠、水墨、玉色玻璃、双角色桌宠。问题不是“没有风格”，而是几个窗口和控件的层级还不够清楚：

- 右键菜单、状态窗口、番茄钟、城市设置窗口都像同一种玉色面板，功能差异不够明显。
- 一些文案和符号在源码里出现乱码，后续维护和多语言检查会很困难。
- 角色本身很有辨识度，但工具窗口里“岳七 / 沈九”的角色感不够强。
- 动效很多，但优先级不够明确，有时天气、气泡、面板动画会互相抢注意力。

这轮优化的目标是：**不改游戏逻辑、不换技术栈，只把 UI 做得更清楚、更稳定、更有角色感。**

## 2. 优先级建议

### P0：先修可读性和乱码

这是最应该先做的部分。现在源码里有不少 UI 文案、注释、静态 HTML fallback 和 i18n 字符串读起来像乱码。即使运行时有些文字能被替换，这也会影响后续维护。

建议做法：

- 检查 `src/index.html`、`src/data/i18n.js`、托盘菜单、番茄钟、城市设置、更新弹窗里的用户可见文案。
- 把乱码恢复成正常 UTF-8 中文、英文、日文。
- 少用容易缺字体或显示异常的 emoji / 特殊符号。
- 给关键 UI 文案加一个简单测试，至少确认 `zh`、`en`、`ja` 都能取到正常字符串。

完成标准：

- 打开源码能读懂 UI 文案。
- 主窗口、右键菜单、托盘菜单、番茄钟、城市设置、更新弹窗不再出现乱码。
- 多语言切换后关键按钮不显示错字、乱码或空文本。

## 3. 右键菜单怎么优化

当前右键菜单能用，但扫读速度还可以更快。它现在主要依赖文字和一些不稳定符号，用户需要仔细读才知道每个操作是什么。

建议做法：

- 把菜单项分组：
  - 照顾：喂食、摸头
  - 修炼 / 休息：修炼、休息
  - 查看：状态
- 每个菜单项前面使用稳定的小图标或 CSS 图形，不依赖可能乱码的 emoji。
- 宠物忙碌时，不只是把按钮变灰，最好显示一个简短原因，例如“正在互动中”。
- hover 时不要让文字位置大幅移动，避免菜单看起来跳动。

完成标准：

- 用户一眼能看出哪些是照顾动作，哪些是查看动作。
- 禁用状态能说明为什么不能点。
- 中文、英文、日文菜单都不溢出。

## 4. 状态窗口怎么优化

状态窗口现在能展示数值，但角色感不够强。用户看到的是一组玉色状态块，而不是很直观地看到“岳七的状态”和“沈九的状态”。

建议做法：

- 把状态窗口做成更明确的双角色结构：
  - 左侧 / 上方是岳七
  - 右侧 / 下方是沈九
  - 每个角色有自己的头像、名字和专属强调色
- 岳七使用紫色强调，沈九使用玉色强调，和 ADR-033 的角色色保持一致。
- 饥饿、灵力不足、心情低落这类危险状态要更明显。
- 健康状态可以更安静，不需要每条状态都一样抢眼。

完成标准：

- 不仔细读文字，也能看出哪块状态属于哪只宠物。
- 低状态能快速被发现。
- 数值变化时窗口尺寸不抖动。

## 5. 番茄钟和城市设置怎么优化

番茄钟和城市设置是工具窗口，应该更像“好用的小工具”，而不是装饰很重的展示面板。

### 番茄钟

建议做法：

- 计时数字和进度条做成视觉重点。
- 宠物图像保留，但作为陪伴氛围，不要抢过计时器。
- 主按钮更明确，例如开始、提前结束、完成退出。
- 减少重复边框、角标、内阴影，让窗口更安静。

完成标准：

- 打开后第一眼看到当前时间和主操作。
- 完成状态有奖励感，但不过度花哨。
- 英文和日文标题不会挤出标题栏。

### 城市设置

建议做法：

- 输入框、确认按钮、当前城市、反馈文案层级更清楚。
- “搜索中 / 设置成功 / 城市不存在 / 网络失败”使用不同但克制的状态样式。
- 错误文案直接告诉用户下一步该做什么，例如“请检查城市名或稍后重试”。

完成标准：

- 用户知道当前城市是什么。
- 设置失败时知道为什么失败。
- 输入和按钮在小窗口里不拥挤。

## 6. 整体视觉怎么收敛

当前多个窗口都用了类似的玉色玻璃效果。统一是优点，但现在有一点“每个窗口都一样”的问题。

建议把窗口分成三类：

| 类型 | 对应窗口 | 视觉重点 |
|---|---|---|
| 快速操作 | 右键菜单 | 小、清楚、好扫读 |
| 角色状态 | 状态窗口 | 岳七 / 沈九身份强 |
| 实用工具 | 番茄钟、城市设置 | 控件清楚、装饰更少 |

可以保留玉色玻璃作为基础，但不同窗口应该有不同重点：

- 右键菜单少装饰，优先速度。
- 状态窗口强调角色。
- 工具窗口强调可用性。

## 7. 动效怎么整理

动效不需要全部减少，但需要明确主次。

建议分三层：

- 第一层：宠物生命感，例如行走、睡觉、互动。
- 第二层：用户操作反馈，例如菜单打开、按钮点击、状态条变化。
- 第三层：环境氛围，例如天气粒子、灵力光效。

规则建议：

- 用户正在操作菜单或按钮时，天气粒子可以暂时降低存在感。
- 宠物互动时，互动气泡和动作优先，环境效果退后。
- `prefers-reduced-motion` 下关闭非必要循环动效。

完成标准：

- 用户操作反馈不会被天气或光效盖住。
- 动效看起来有生命感，但不乱。
- reduced-motion 模式下仍能看懂状态变化。

## 8. CSS 和设计变量怎么整理

现在 `index.css`、`status.css`、`pomodoro.css`、`city-setting.css` 里有一些重复变量。后续如果要改面板颜色、圆角或阴影，可能要改多处。

建议做法：

- 继续使用原生 CSS，不引入 Tailwind、Sass 或 React。
- 把共享颜色、圆角、阴影、字体变量收敛到统一位置。
- 变量命名按用途来，例如：
  - `--panel-bg`
  - `--panel-border`
  - `--accent-yueqi`
  - `--accent-shenjiu`
  - `--feedback-warning`

完成标准：

- 调整通用面板样式时，不需要在多个 CSS 文件里重复改。
- 角色色含义清楚，不出现“变量名是沈九、实际颜色用于岳七”的情况。
- 不增加新的构建复杂度。

## 9. 建议实施顺序

### 第一步：文案和乱码审计

- 修复用户可见乱码。
- 确认中英日三种语言关键 UI 都正常。
- 截图保存当前 UI 状态，方便后续对比。

### 第二步：右键菜单

- 调整分组。
- 替换不稳定符号。
- 优化禁用态和 hover。

### 第三步：状态窗口

- 改成更清楚的双角色结构。
- 加强岳七 / 沈九的角色色。
- 优化低状态提醒。

### 第四步：番茄钟和城市设置

- 降低装饰密度。
- 强化主按钮和反馈文案。
- 检查小窗口和多语言适配。

### 第五步：动效和 CSS 变量

- 整理动效优先级。
- 收敛共享 CSS 变量。
- 补必要测试和截图验证。

## 10. 不做什么

这一轮不建议做这些：

- 不重画宠物素材。
- 不改养成数值、天气同步逻辑、多显示器逻辑。
- 不引入新前端框架或构建工具。
- 不依赖透明 Electron 窗口下不可控的系统桌面模糊。

## 11. 验证方式

真正开始改 UI 时，每一阶段都应该验证：

- `npm test` 或相关 focused test 通过。
- 主桌宠点击穿透仍正常。
- 右键菜单仍能正确切换鼠标事件。
- 状态、番茄钟、城市设置窗口仍可拖动。
- 中文、英文、日文不溢出、不乱码。
- 高 DPI / 多显示器下菜单、气泡、特效尺寸仍正确。

## 12. 待确认问题

- 是否先做“乱码和可读性修复”，再做视觉刷新？
- 状态窗口是否接受更明显的双角色布局？
- 右键菜单更适合“图标 + 文本”，还是保留纯文本？
- 番茄钟是否要更像工具，减少仙侠装饰？
