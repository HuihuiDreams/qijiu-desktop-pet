# 桌面宠物可视化皮肤选择窗 (Visual Skin Selector) 实施计划

## 1. 目标与范围

项目当前内置 `default`、`birds`、`animal_ears`、`school_au` 四套皮肤。现有托盘菜单以单选列表切换皮肤；当皮肤增长至 10～30 套时，文字列表既冗长，也无法表达皮肤外观。

本功能将该单选列表**替换为一个“选择皮肤…”画廊入口**：在鼠标所在显示器上打开轻量、一次性完成选择的可视化窗口。MVP 只展示静态封面，不引入搜索、分类、在线皮肤管理或多帧预览。

## 2. 已确认的架构决策

### 2.1 交互和托盘入口

- 托盘中的现有“切换皮肤”单选子菜单替换为单个 `[选择皮肤…]` 项；不保留重复的文字单选入口。
- 点击入口时，若选肤窗已存在则刷新数据、重新定位、置顶并聚焦；否则按需创建窗口。MVP 不新增快捷键或桌宠内交互入口。
- 选肤窗使用无边框透明窗口，并对齐状态窗口的安全配置和视觉语言：`transparent: true`、`frame: false`、`hasShadow: false`、`skipTaskbar: true`、不可调整大小，以及 `alwaysOnTop: 'floating'`。加载完成后禁止新窗口和页面导航。
- 窗口包含关闭按钮和 `Escape` 退出。卡片点击成功后立即隐藏；切换失败则保留窗口并显示可读错误，供用户重试。

### 2.2 画廊尺寸、布局和无障碍

- 选肤窗在当前显示器的 `workArea` 内居中。初始内容区目标为约 `720 × 520` DIP；最终尺寸必须经由 `workArea` clamp，保留最小可用边距，不能越过任务栏或小屏边界。
- 画廊使用自适应网格：卡片设定最小宽度，超过可见高度时仅画廊区域纵向滚动，标题栏与关闭按钮固定可见。30 套皮肤必须可访问且不需要缩放窗口。
- 当前皮肤必须有文字和视觉双重标识，不能只依赖颜色；卡片须具备按钮语义、键盘 Tab 焦点和明确的 `aria-label`。
- 继续复用 `index.css` 的变量和 `xianxia-panel` 纹理，而不是复制一套颜色、字体和边框变量。

### 2.3 主进程拥有皮肤元数据与切换权

选肤页不扫描文件系统、不拼接本地路径，也不自行发送 `switch-skin`。主进程新增并维护以下边界：

```text
SkinGalleryItem = {
  id: string,
  displayName: string,
  previewUrl: string, // 仅允许 pet-asset://skin/<id>/…
  isCurrent: boolean,
}
```

- `get-skin-gallery-items` 返回基于 `scanAvailableSkins()` 的上述数据。展示名复用主进程的本地化皮肤名逻辑，未知 ID 回退为 ID。
- 预览图由主进程解析。按 `right.webp`、`left.webp`、`cultivate.webp` 的顺序选择；资源缺失时回退到 `default/right.webp`，保证每张已扫描卡片均可显示。URL 必须通过既有 `createAssetUrl()` 构造，以兼容开发目录和生产加密资产。
- `select-skin` 只接受 `skinId`。主进程以 `isAllowedSkinId(skinId, scanAvailableSkins())` 校验，再调用唯一的 `selectSkin(skinId)` 流程：更新 `currentSkinId`、向桌宠主窗口发送 `switch-skin`、同步番茄钟状态并刷新托盘菜单。
- 现有渲染器确认接口 `set-current-skin` 保持“桌宠已完成换装后记录当前状态”的职责；它不得反向发送 `switch-skin`，避免递归/竞态。托盘和选肤窗都调用同一 `selectSkin()`，不各自维护切换逻辑。
- 为选肤窗使用最小化的独立 preload，只暴露 `getSkinGalleryItems()`、`selectSkin(id)`、`closeSkinSelector()`；不把完整 `electronAPI` 暴露给该页面。页面 CSP 必须保持 `default-src 'none'`，并仅允许 `self`、`data:` 和 `pet-asset:` 图片来源。

### 2.4 生命周期与失焦规则

- 第一次通过托盘打开时创建；之后在本应用会话内 `hide()`/`show()` 复用。应用启动时不预创建，避免影响冷启动和常驻内存。
- 每次显示前均重新读取画廊数据，以反映当前皮肤和新增资源；隐藏后不保留“切换中”状态。
- 正常失焦、关闭按钮和 Escape 均隐藏窗口。应用退出时随主进程销毁。
- 选择期间设置 `selectionInFlight`：先等待 `select-skin` IPC 成功，再隐藏窗口；此期间忽略 `blur`，防止点击卡片触发失焦而中断请求。失败后清除该状态并保留窗口。

### 2.5 多显示器、高 DPI 与性能

- 这是独立原生 `BrowserWindow`，定位应复用状态窗口的原生 Electron 模式：`screen.getCursorScreenPoint()` → `screen.getDisplayNearestPoint()` → `display.workArea`。**不使用 `displayBounds.js`**；该模块服务于桌宠覆盖窗口内部坐标换算，不是原生弹窗定位层。
- 手工验收至少覆盖主屏、负坐标副屏，以及 100%、125%、150% DPI；检查弹窗位于鼠标所在屏、完全落入 work area，且卡片物理尺寸和点击区域正常。
- 性能指标按“托盘点击到窗口可交互”衡量：会话内复用窗口在 30 张本地 WebP 封面下 P95 不超过 100 ms；首次按需打开不超过 250 ms。记录开发模式与打包模式的测量结果。若未达标，先分析资源解码和窗口创建时间，再决定是否预热，不能预先引入常驻隐藏窗口。

## 3. MVP 包含与排除

### 包含

- 一个托盘画廊入口及单实例选肤窗。
- 静态封面、显示名、当前选择标识、键盘和鼠标选择。
- 主进程校验的 IPC 切换、失败反馈与安全的资源 URL。
- 失焦隐藏、会话内复用、当前屏居中和 DPI 验收。
- 单元测试、Electron smoke 测试，以及实现提交时的 `CHANGELOG.md` 和 `docs/structure.md` 同步更新。

### 排除

- 搜索、标签、分类和排序配置。
- 同屏多卡片动画或实时序列帧预览。
- 第三方皮肤下载、解压、删除、在线商城或皮肤编辑。
- 新增全局快捷键和桌宠内入口。

## 4. 实施任务

### Task 1：定义主进程数据与统一切换流程

**描述：** 提取可复用的 `selectSkin()`，让托盘与选肤窗经由同一主进程流程切换；构建受控的画廊数据。

**验收标准：**

- [ ] 托盘入口替换为 `[选择皮肤…]`，不再渲染皮肤单选子菜单。
- [ ] `get-skin-gallery-items` 返回已本地化、带受控 `pet-asset:` 预览 URL 和当前标记的数据。
- [ ] 非法 ID 被拒绝；托盘与画廊均只通过 `selectSkin()` 发送一次 `switch-skin`。

**验证：** 通过单元测试覆盖排序、未知名称、预览回退、非法 ID 和托盘/IPC 共用流程。

**依赖：** 无。

### Task 2：创建并管理选肤窗口

**描述：** 增加单实例 BrowserWindow、当前显示器定位、`hide/show` 复用和关闭/失焦状态机。

**验收标准：**

- [ ] 重复点击入口不会创建第二个窗口，且每次展示刷新数据与位置。
- [ ] 选中、失焦、Escape 与关闭按钮遵循已定义的隐藏规则；选择中的 blur 不会取消请求。
- [ ] 窗口配置、导航限制和最小化 preload 符合既有 Electron 安全边界。

**验证：** 对窗口状态机做聚焦测试；以 Electron smoke 覆盖重复打开、Escape、失焦和成功选择。

**依赖：** Task 1。

### Task 3：实现画廊页面

**描述：** 新增独立 HTML/CSS/JS 与专用 preload，按受控元数据渲染可滚动卡片网格。

**验收标准：**

- [ ] 30 张卡片不会溢出窗口；当前皮肤、图片回退、空状态和 IPC 错误均可理解。
- [ ] 键盘、鼠标与屏幕阅读器都能定位和选择卡片。
- [ ] 样式复用现有修仙面板变量，CSP 仅允许预期资源。

**验证：** DOM 测试或等价的渲染测试；Electron smoke 点击一张卡片并确认桌宠收到切换；人工检查视觉一致性。

**依赖：** Task 1、Task 2。

### Task 4：多屏、性能和回归验证

**描述：** 在真实 Electron 环境验证边界条件并记录性能数据。

**验收标准：**

- [ ] `npm test` 和 `npm run qa:electron:smoke` 全部通过。
- [ ] 在 100%、125%、150% DPI 和至少一个副屏场景下完成手工检查。
- [ ] 已记录首次与复用打开的测量值；若不满足目标，先提交瓶颈证据和后续方案，不静默放宽指标。

**验证：** 自动化命令、控制台检查和手工多屏/DPI 检查。

**依赖：** Task 1～Task 3。

### Task 5：同步发布文档

**描述：** 将最终窗口边界、IPC 和可见行为同步到项目文档。

**验收标准：**

- [ ] `CHANGELOG.md` 在正确英文标题下记录用户可见变化。
- [ ] `docs/structure.md` 说明选肤窗、专用 preload 和主进程职责；若实施中改变本计划的关键架构决策，新增 ADR。

**验证：** 提交前审查文档与实现一致，执行项目既有测试。

**依赖：** Task 4。

## 5. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 卡片点击与 `blur` 竞争 | 选中后未切换或窗口异常关闭 | `selectionInFlight` 直到 IPC 返回，再隐藏窗口 |
| 新皮肤缺少约定封面 | 空白卡片或 404 | 主进程固定优先级并回退到默认皮肤封面 |
| 通过渲染层拼路径 | 绕过加密资产协议或产生路径错误 | 仅由主进程构造 `pet-asset:` URL |
| 小屏/高 DPI 溢出 | 弹窗被裁切、点击区域偏移 | 基于 `workArea` clamp、滚动网格和多 DPI 手测 |
| 30 张封面造成首次卡顿 | 不满足轻量目标 | 按需创建、会话复用、先测量再决定是否预热 |
