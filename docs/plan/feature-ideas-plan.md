## 1. Background & Refinement

### 1.1 问题陈述

当前版本已实现基础养成系统，包括：

- 饱腹
- 灵力
- 心境
- 好感
- 基础 CP 互动

下一阶段需要提升两个核心指标：

1. **长期留存**：让用户有理由持续打开桌宠。
2. **日常价值**：让桌宠不仅是装饰，也能提供轻量生产力与环境陪伴。

因此，功能扩展将围绕三个方向展开：

- 生产力工具化
- 环境互动与沉浸感
- 收集与养成深度

### 1.2 核心假设

- 用户希望桌宠不仅是视觉装饰，也能提供轻量实用价值，例如专注、提醒、任务管理。
- 桌宠能感知时间、天气、窗口状态后，会更像“活在桌面上”的角色。
- 可收集内容，如皮肤、配件、回忆快照、图鉴，是提升长期留存的重要动力。
- 功能应优先服务“角色感”和“陪伴感”，而不是把桌宠做成复杂效率软件。

### 1.3 产品原则

- **轻量优先**：功能不能显著增加 CPU、内存、电量消耗。
- **角色化表达**：所有工具功能都应通过角色动作、台词或世界观包装呈现。
- **隐私透明**：涉及窗口、系统状态、天气、截图的功能必须明确权限与数据边界。
- **可关闭**：所有环境感知、系统监控、外部 API 功能都必须提供开关。
- **可降级**：权限不足、API 不可用、依赖异常时，功能应安全降级，不影响桌宠基础运行。

### 1.4 非目标

暂不考虑以下方向：

- 大型 3D 场景开发
- 多人联机社交
- 重度任务管理系统
- 完整日历 / 邮件集成
- 商业化皮肤商店
- 自动读取用户敏感内容
- 无提示截图或上传截图

## 2. Functional Specification

## 2.1 Productivity & Utility

### 2.1.1 “苍穹山派”番茄钟

#### 功能概述

用户开启专注模式后，角色进入“闭关”状态。计时期间，桌宠通过动画、台词和轻提示帮助用户保持专注。

#### 预期能力

- 右键菜单增加“开始闭关”入口。
- 支持选择专注时长。
- 专注期间显示倒计时。
- 角色进入闭关动画或打坐状态。
- 时间结束后展示结算界面。
- 根据完成情况给予灵石、好感度或心境奖励。
- 可配置是否启用“监督台词”。

#### 可选扩展

- 检测频繁切换窗口后触发沈九冷嘲热讽台词。
- 支持短休息、长休息。
- 支持连续闭关成就。
- 支持每日专注统计。

#### 边界

窗口切换检测只能用于本地判断，不应上传应用名、窗口标题或用户行为数据。

---

### 2.1.2 宗门事务 To-Do List

#### 功能概述

将待办事项包装成“宗门事务”。用户完成任务后，获得轻量养成反馈。

#### 预期能力

- 新增、编辑、完成、删除任务。
- 支持任务奖励，如灵石、好感度、心境。
- 支持简单任务分类，例如修炼、杂务、外出、紧急。
- 完成任务后触发角色称赞、吐槽或 CP 互动。
- 支持本地持久化。

#### 可选扩展

- 每日宗门任务。
- 连续完成奖励。
- 任务失败 / 过期后的角色反馈。
- 与番茄钟联动：任务可绑定闭关时长。

#### 边界

不做复杂项目管理，不支持多人协作，不做云同步。

---

### 2.1.3 系统状态实时映射

#### 功能概述

将 CPU、内存、电量等系统状态映射到角色状态或视觉特效中，让桌宠感知设备状态。

#### 预期能力

- CPU 占用率影响“灵气流转”速度或特效强度。
- 内存占用过高时，角色出现疲惫或警觉状态。
- 电量不足时，角色触发“灵力衰竭”提醒。
- 充电时触发“灵力恢复”表现。
- 用户可关闭所有系统监控功能。

#### 建议依赖

- `node-os-utils` 或同类系统指标库。
- 接入前需要锁定版本并验证跨平台表现。
- `node-os-utils` 2.x 是一次较大重写，官方 npm 页面说明其强调 TypeScript、跨平台系统监控、缓存、事件式监控和错误处理，并提示存在从 v1.x 到 v2.x 的 breaking changes。

#### 边界

- 默认采样频率不应过高。
- 建议采样间隔不低于 3–5 秒。
- 不记录历史系统性能数据。
- 不上传任何系统指标。
- 低电量提醒需要防抖，避免频繁弹出。

## 2.2 Environment & Immersion

### 2.2.1 窗口感知交互

#### 功能概述

桌宠能够感知当前活动窗口的位置，并在窗口顶部行走、坐下或做出反应。

#### 预期能力

- 获取当前活动窗口坐标与尺寸。
- 将窗口顶部边缘识别为可站立平台。
- 角色可在窗口顶边缘行走。
- 当前窗口最小化或切换时，角色触发寻找、无聊或跳回桌面状态。
- 用户可关闭窗口感知能力。

#### 建议依赖

- 可调研 `active-win` 或 `get-windows`。
- `get-windows` 可获取 active window 和 open windows 的 metadata，包括 `title`、`id`、`bounds`、`owner`、`URL` 等。
- `get-windows` 支持 macOS 10.14+、Linux 和 Windows 7+，但跨平台权限、窗口系统差异和全屏行为仍需要实测。

#### 边界

- 不展示、不存储、不上传窗口标题。
- 默认只使用窗口 `bounds`。
- 如果权限不足或获取失败，回退到普通桌面行走。
- 对全屏应用、虚拟桌面、多显示器场景需要单独测试。
- 不应影响用户点击窗口和正常操作。

---

### 2.2.2 时空同步系统

#### 功能概述

桌宠根据本地时间、昼夜和天气变化，切换状态、台词、特效或道具。

#### 预期能力

- 根据本地时间切换早晨、白天、黄昏、深夜状态。
- 深夜自动进入睡眠或低活跃状态。
- 雨天显示雨滴、油纸伞或避雨动作。
- 雪天显示雪粒子、披风或怕冷动作。
- 晴天显示轻快状态或晒太阳动作。
- 支持离线 fallback，仅使用本地时间。

#### 建议依赖

- 天气 API 可优先调研 Open-Meteo。
- Open-Meteo `/v1/forecast` 可按经纬度返回 JSON 格式的小时级天气预报。
- Open-Meteo 官方页面说明其无需 API key，并覆盖多个国家气象模型。

#### 隐私边界

- 不默认获取精确定位。
- 推荐让用户手动选择城市，或只保存模糊位置。
- 不上传用户身份信息。
- 天气请求失败时不影响主程序。
- 提供“禁用天气同步”开关。

## 2.3 Gameplay & Collection

### 2.3.1 皮肤与配件系统

#### 功能概述

支持角色外观切换、时期形态切换和挂件式配件，为长期收集提供基础。

#### 预期能力

- 支持角色皮肤切换。
- 支持不同时期外观，例如弟子服、峰主服、现代 AU。
- 支持配件挂载，例如折扇、玄肃剑。
- 支持动作与皮肤的兼容校验。
- 支持默认皮肤回退。
- 支持本地配置持久化。

#### 建议设计

皮肤系统建议拆成两层：

| 层级 | 说明 |
|---|---|
| Base Skin | 替换角色主体外观，如弟子服、峰主服、现代 AU |
| Accessory | 挂件式资产，如折扇、剑、披风、伞 |

这样可以避免每个皮肤都重复绘制所有道具，也方便后续组合式收集。

#### 边界

- 第一阶段不做商店经济。
- 第一阶段不做付费皮肤。
- 第一阶段不做用户上传皮肤。
- 必须定义资产命名、尺寸、锚点、动作兼容规则。

---

### 2.3.2 随机奇遇与收藏图鉴

#### 功能概述

当用户触发罕见互动、完成连续任务或达成特殊条件时，系统自动解锁回忆快照或图鉴内容。

#### 预期能力

- 罕见互动触发“回忆快照”。
- 解锁内容保存到本地图鉴。
- 图鉴中可查看已解锁插画、台词或事件记录。
- 支持按角色、主题、时间分类。
- 支持重复触发但不重复解锁。

#### 可选扩展

- 特定天气触发特殊事件。
- 深夜触发低概率 CP 对话。
- 连续闭关触发修炼事件。
- 完成宗门任务链触发剧情片段。

#### 边界

- 自动截图必须只截取桌宠自身画面或应用窗口，不应截取用户整个桌面。
- 如果支持用户自定义截图，必须由用户主动触发。
- 图鉴数据默认本地保存。

## 4. Dependencies

| 能力 | 可能依赖 | 备注 |
|---|---|---|
| 系统指标 | `node-os-utils` 或替代库 | 需确认 2.x breaking changes 与跨平台表现 |

| 粒子特效 | 当前渲染层 / Canvas / WebGL | 需评估性能 |
| 本地持久化 | 当前存储层 | 需定义版本迁移 |

## 5. Task Breakdown

### Phase 1：生产力与工具层

#### Task 1：番茄钟基础实现

范围：

- 右键菜单增加“开始闭关”。
- 支持选择专注时长。
- 实现倒计时逻辑。
- 增加闭关动画状态。
- 时间结束后展示结算界面。

验收标准：

- 用户可以开始、暂停、取消、完成一次闭关。
- 倒计时结束后能稳定触发结算。
- 角色状态能正确进入和退出闭关。
- 应用重启后不会残留异常闭关状态。
- 番茄钟关闭后不影响基础桌宠互动。

---

#### Task 2：To-Do List 基础实现

范围：

- 新增任务。
- 完成任务。
- 删除任务。
- 本地保存任务。
- 完成任务后给予奖励反馈。

验收标准：

- 用户可以完成一条宗门任务。
- 完成后任务状态正确更新。
- 奖励只发放一次。
- 重启后任务列表仍然存在。
- 空任务、超长任务、重复任务有基础处理。

---

### Phase 2：环境感知层

#### Task 3：系统监控数据接入

范围：

- 引入系统指标依赖。
- 获取 CPU、内存、电量信息。
- 主进程采样，渲染进程只接收抽象状态。
- 将指标映射为灵气特效等级。

验收标准：

- CPU / 内存变化能影响角色表现。
- 采样频率可配置。
- 关闭功能后不再采样。
- 依赖异常时应用不崩溃。
- 不记录、不上传系统指标。

---

#### Task 4：窗口边界检测

范围：

- 获取活动窗口 bounds。
- 将窗口顶边缘抽象为 platform。
- `MovementSystem` 支持平台行走。
- 焦点窗口变化时更新 platform。

验收标准：

- 宠物能在普通窗口顶部停留。
- 窗口移动后 platform 位置能更新。
- 窗口最小化后宠物能回退到桌面行为。
- 全屏应用下不出现异常跳跃。
- 关闭窗口感知后恢复普通移动逻辑。

---

#### Task 5：天气 API 对接与时段状态

范围：

- 支持用户手动设置城市或坐标。
- 请求天气 API。
- 映射天气状态到视觉特效。
- 增加本地时间状态切换。
- 提供离线 fallback。

验收标准：

- 晴 / 雨 / 雪等天气能映射到对应表现。
- API 请求失败时应用不崩溃。
- 用户关闭天气同步后不再发起请求。
- 深夜状态无需联网也能正常触发。
- 不默认请求精确定位权限。

---

### Phase 3：收集与美化层

#### Task 6：皮肤系统重构

范围：

- 定义皮肤配置结构。
- 定义配件锚点结构。
- 在 `SpriteView` 或等价渲染层增加皮肤切换接口。
- 准备至少一套测试皮肤。
- 支持默认皮肤回退。

验收标准：

- 用户可以切换皮肤。
- 更换皮肤后基础动作正常显示。
- 缺失素材时回退到默认皮肤。
- 配件不会明显错位。
- 配置保存后重启仍生效。

## 7. Risks & Mitigation

| 风险 / 挑战 | 影响 | 缓解策略 |
|---|---:|---|
| 性能开销 | 中 | 限制检测频率；系统指标采样不低于 3–5 秒；粒子特效可关闭 |
| 美术资源压力 | 高 | 优先实现皮肤配置与回退逻辑；素材分批引入 |
| 外部 API 稳定性 | 中 | 提供离线 fallback；失败后不阻塞主流程 |
| 原生依赖兼容性 | 高 | 锁定依赖版本；按平台测试；依赖失败时安全降级 |
| 隐私争议 | 高 | 默认关闭敏感感知能力；只本地处理；提供权限说明 |
| 多显示器 / 全屏异常 | 中 | 将窗口感知作为可选能力；异常时回到桌面移动模式 |
| 功能膨胀 | 中 | 每个功能单独 spec；每期只做最小可用闭环 |
